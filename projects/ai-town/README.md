# 实战项目：晨光 AI 小镇

[仓库首页](../../README.md) · [第一次打开](../../START_HERE.md) · [五阶段路线](../../topics/agent-systems/ROADMAP.md) · [实际界面截图](../../assets/ai-town-preview.png)

三位居民住在同一座小镇里。每位居民有职业、目标、所在地点和精力；推进时间，可以观察他们工作、休息、相遇，以及留下的近期记忆。

**当前代码：规则对照 + 单个 NPC 的 DeepSeek 接入。** 规则模式由条件判断选择动作、使用固定对白；DeepSeek 模式向模型请求小林的动作与对白，阿岚和小乔仍由规则控制。模型模式不先经过“低精力必须回家”或“同一人间隔四轮再聊”的分支。

**真实 DeepSeek Flash 调用仍待验证。** 接入代码和模拟响应检查不能替代真实服务验证，也不代表学习者已经通过阶段。准确模型 ID 仍待按用户提供的[官方文档](https://api-docs.deepseek.com/zh-cn/)确认；后续目标生成和计划调整仍待实现，详见[当前学习重点](../../topics/agent-systems/README.md#当前学习重点)。

## 启动网页

需要 Python 3.10 或更新版本，仅用标准库，无第三方依赖。

Mac 的 **`start-deepseek-mac.command`** 启动模型模式，并在终端提示输入模型 ID 和密钥；`start-mac.command` 与 Windows 的 `start-windows.bat` 启动规则模式。启动入口会选择空闲端口并自动打开浏览器，具体操作见[Mac 启动步骤](../../START_HERE.md#在-mac-上启动-deepseek-模式)。

也可以从仓库根目录启动 DeepSeek 模式：

```bash
python3 projects/ai-town/server.py --mode deepseek --prompt-key --port 0 --open-browser
```

模型 ID 可通过 `DEEPSEEK_MODEL` 或 `--model` 指定；密钥可通过 `DEEPSEEK_API_KEY` 提供，或在交互式终端隐藏输入。密钥不写入源码、网页或日志。默认每次启动最多发起 5 次模型请求（含失败），不自动重试；`--max-model-calls` 可在启动时明确设置 1 至 24 次。

规则模式命令为：

```bash
python3 projects/ai-town/server.py --open-browser
```

默认监听 `127.0.0.1:8765`，在**运行程序的同一台电脑**上访问终端显示的地址。云端程序不会自动映射到自己电脑的 localhost。端口被占用时加 `--port 0` 自动选择空闲端口。终端按 `Ctrl+C` 停止。

所有访问者共享当前进程中的同一个小镇，本项目用于个人本地学习。

## 网页操作

- **推进一轮**：小镇时间前进 30 分钟，居民依次执行一个动作。
- **自动运行 / 暂停**：仅规则模式可用；DeepSeek 模式手动逐轮观察。默认一天最多 24 轮。
- **选择居民**：查看决策来源、状态、行动前观察、行动原因和近期记忆；模型角色还可展开发送内容、返回动作和 token 用量（模型处理的文本单位）。
- **重置小镇**：清空当前运行记录，重新读取 `world.json`；模型模式保留本次启动已使用的请求次数。

地点包括咖啡馆、图书馆、广场、居民小屋和公园。当前在地点之间直接移动，没有逐格寻路和碰撞系统。

## 当前实践：小林的第一次真实模型决策

先按启动说明配置模型，选中小林，手动推进一轮。记录三件事：发送给模型的角色、目标与观察；模型返回的动作；执行后小镇真正发生的变化。模型选择交谈时，核对接收者的记忆中是否出现了原话。

成功执行前程序会检查动作和对象是否合法。接口超时、响应无效或动作不合法时，页面显示错误，整轮世界状态保持原样；模型请求的尝试次数仍会增加。界面不会把规则回退伪装成模型成功。

本次只验证一次真实调用与执行。模型提出长期目标、多步规划以及所有居民都由模型控制，是后续内容。

## 规则入门练习：只改变一个数字

本次目标是认识“状态会影响决策”，请使用规则模式。先保留小林的 `energy: 75`，重置后推进一轮，记录行动、地点和精力。然后只把这个数改为 `20`，保存文件，先预测，再重置并推进相同的一轮。模型模式可以权衡目标与状态，行为不必复刻规则。

**两次都从第 0 轮开始，只改一个参数。** 把预测与实际结果写进[学习记录](../../topics/agent-systems/README.md#学习记录)。现在不必读懂整个程序，也不把这项小练习视为整个阶段已过关。

## 从小镇理解 Agent

```text
世界状态 → observe()：我看到了什么
                ↓
       规则 choose_action() / 模型 decide()：下一步做什么
                ↓
       apply_action()：校验并执行行动
                ↓
         世界更新 + 事件记忆
                └────────→ 下一轮观察
```

DeepSeek 模式将角色、`goal`、当前观察、自己的记忆和公开地图交给模型，程序负责检查和执行行动；模型生成的对白实际传递给对方并写入双方记忆。规则模式的 `goal` 仍只是展示文字，决策使用精力、地点、职业地点和近期打招呼记录。

每轮居民按配置顺序依次行动，后行动的居民能看到前面行动造成的变化。侧栏的“行动前的观察”可能与行动后的当前位置不同。

每人最多保留 12 条自己的近期事件。另有一份按居民 ID 记录的最近交谈轮次，用于判断能否再次找同一个人聊天。这些记录都存在内存中，重置或服务重启会清空。长期记忆检索和存读档是后续阶段的目标。

## 规则对照练习：记住跟谁聊过

这项练习展示怎样记录交谈对象并据此选择动作，仍然完全由脚本决策。已经理解后即可转向真实模型实践；模型模式如何使用这些记忆，由角色、目标和当前情境共同影响。

在不需要优先回家或休息时，NPC 会逐个检查附近的人：距离上次与这个人交谈不足 4 轮就跳过，继续检查下一人；没有聊过或已间隔至少 4 轮，就选择与这个人交谈。如果没有可聊天的人，则继续判断前往工作地点、工作等行动。

“轮”是世界轮次，每轮为 30 分钟模拟时间。同一轮中，每位 NPC 各选择一次行动；交谈没有额外的内部轮次。比如第 6 轮和阿岚聊过，第 8 轮仍不能再次找他，第 10 轮就可以；这不限制期间与其他人聊天。

每次成功交谈，双方都更新自己的 `last_chat_ticks`，并在交谈事件中保存对方的 `partner_id`。这个字典记录“对方 ID → 最近交谈轮次”，不会因为最近 12 条事件被裁剪而提前忘记间隔。

选择对象的关键代码在 [town.py](town.py) 的 `choose_action()`：

```python
for person_id in observation["nearby_ids"]:
    last_chat_tick = observation["last_chat_ticks"].get(person_id)
    if last_chat_tick is not None and observation["tick"] - last_chat_tick < 4:
        continue
    return {"type": "talk", "target": person_id,
            "reason": "附近有居民，且最近四轮内没有与对方交谈，打个招呼。"}
```

`for` 逐个查看附近居民；`.get()` 查上次交谈轮次，没有记录时得到 `None`；`continue` 跳过当前居民，检查下一位；`return` 选定一个动作并结束本次选择。Python 的 `pass` 只是占位语句，不会跳过当前居民。

从默认配置启动**规则模式**后，推进一轮并查看行动记录：小林先找阿岚，阿岚接着跳过小林、找小乔，小乔再跳过阿岚、找小林。同一轮可以参与不同对象的交谈，但每人仍只主动选择一次行动。规则角色精力不足时，回家或休息仍然优先；模型角色自行权衡。

修改 `town.py` 后，停止并重新启动服务，使用新打开的页面；仅点击网页上的“重置小镇”不会重新加载 Python 代码。本机若做过精力参数或规则实验，更新文件前先保留自己的修改。
