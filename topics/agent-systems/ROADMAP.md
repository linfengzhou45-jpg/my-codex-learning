# 用 AI 小镇学习 Agent：五阶段学习阶梯

[返回主题首页](README.md) · [六种学习方法](../../LEARNING_METHODS.md) · [小镇项目与首次练习](../../projects/ai-town/README.md)

**贯穿项目：虚拟 AI 小镇。** 从零基础开始，用 Python 逐步让三个 NPC（非玩家角色）感知周围环境、决定行动、与他人交流，并记住自己的经历。终点是能独立设计、运行、检查和修改这个项目。

**当前代码：规则驱动演示，尚未接入大模型。** 已有运行、精力对比和规则解释等局部练习记录；阶段 1 尚未整体验收。下一项实践优先进行阶段 2 的单个 NPC 真实模型决策，基础知识随实践补充。当前已有短期事件与交谈对象记录；下文模型调用、目标规划、记忆检索和存读档等仍是待实现目标。

默认使用 **Python + JSON + 命令行**，网页帮助观察小镇；规则模式不需要模型账号，真实模型实践需要可用的模型服务。课程围绕模型自主选择行动、生成对白、提出短期目标及调整计划展开。

## 我们到底在构建什么

- **世界状态**：程序保存的时间、地点、角色位置和角色需求等事实。
- **NPC / Agent**：NPC 是小镇中的角色；这里要学习的模型 Agent 则能根据可见信息提出行动，并利用行动反馈继续决策。
- **决策与执行**：模型提出“想做什么”，程序判断是否合法并真正更新世界；模型说“到了广场”不等于程序中的位置已经改变。
- **规则驱动起步**：先用条件判断理解数据与行为的关系，随后替换决策部分，保留世界规则和执行边界。
- **策略与约束**：强制低精力回家、四轮内不重复聊天属于规则模式的行为策略；模型可以根据目标和记忆自行权衡。可用地点、动作的前提条件和实际资源变化属于程序负责的世界约束。
- **自主性与能力范围**：模型决定当前要做什么，并逐步学会组合动作和调整目标。新行为不必逐条写成条件分支；但世界尚不支持的能力仍需实现对应动作，不能只靠模型描述就当作已经发生。

```text
小镇状态 → NPC 能看到的信息 → 选择行动 → 程序校验并执行
    ↑                                          ↓
    └────────────── 更新世界，记录结果 ───────────┘
```

## 总体路线

| 阶段 | 学习重点 | 动手产物 | 过关证据 |
| --- | --- | --- | --- |
| 1. 让小镇动起来 | Python、终端、JSON、世界状态 | 三个规则驱动 NPC 的小镇 | 能运行、修改数据、预测并解释变化 |
| 2. 给一个 NPC 接上模型 | API、结构化决策、配置、错误处理 | 一个 NPC 的真实模型决策 | 真实调用记录，以及失败处理演示 |
| 3. 让行动形成循环 | 感知、决策、执行、反馈、预算 | 有行动边界的 NPC Agent | 完整行动轨迹，非法动作拒绝与受控停止 |
| 4. 让角色有各自的经历 | 局部观察、独立记忆、交流、存读档 | 能持续互动的小镇 | 固定场景与 12 项评测记录 |
| 5. 独立完成项目 | 模块化、可复现运行、需求变更 | 他人也能运行的小镇项目 | 新环境复现和自己完成的一项功能 |

所有阶段均待学习者提交证据。按能力晋级，不按课程数量晋级；已有基础时可以直接尝试验收，遇到缺口再补相应知识。

## 阶段 1：让小镇动起来

**目标：** 能运行一个三角色小镇，理解角色数据怎样经过 Python 规则变成可观察的行动。本阶段不调用模型。

### 必备知识

- **终端与路径**：运行命令，区分当前目录、相对路径和绝对路径，找到程序入口。
- **Python 基础**：变量、条件、循环、函数、列表和字典；能读懂“遍历角色，根据状态选择行动”。
- **JSON 与文件**：JSON 是保存结构化数据的文本格式；能读写角色配置，并区分文件内容与运行中的数据。
- **世界与时间步**：世界状态保存事实；时间步表示小镇向前推进一次，不必等于现实中的一秒。
- **异常与开发工具**：定位错误行，识别文件缺失和 JSON 格式错误；了解 Python 解释器、虚拟环境及 Git 改动。

### 动手产物

先使用[项目说明中的首次练习](../../projects/ai-town/README.md)：**只修改一个 NPC 的一个数据字段，重新运行并观察变化。** 修改前保留原值并写下预测，修改后记录实际输出；先不要求重写程序。

之后逐步读懂三个 NPC 的初始状态、规则判断和世界更新，学会添加一个简单状态字段及其对应规则。每次只改一处，确保能看出改变与结果之间的联系。

### 容易犯的错误

- 把 JSON 当成会自己执行的程序，忽略实际读取和使用该字段的 Python 代码。
- 一次改多个数值，结果变了却不知道由哪一处造成。
- 把日志里的描述当作真实状态，没有核对角色位置或数值是否更新。
- 看到角色在走动，就以为已经接入 AI；规则判断与模型决策需要明确区分。
- 把 AI 写好代码当成自己已经会写，或不检查输出就标记完成。

### 进入下一阶段前的能力标准

- [ ] 按项目说明独立运行小镇，找到三个 NPC 的初始数据及至少一次状态更新。
- [ ] 修改一个 NPC 数据字段，记录原值、新值、预测和实际结果，并解释它经过哪条规则影响行为。
- [ ] 用自己的话说明 JSON 文件、Python 程序和运行日志分别承担什么作用。
- [ ] 在练习副本中制造一次 JSON 格式错误或文件缺失，找到原因并修复；不破坏原始配置。
- [ ] 在理解已有代码后独立增加一个简单状态或判断，验证正常情况和一个边界情况。
- [ ] 能说明自己使用的 Python 解释器，查看 Git 改动，并识别缓存、虚拟环境等不应提交的文件。

## 阶段 2：给一个 NPC 接上模型

**目标：** 让一个 NPC 根据角色、目标、可见状态和记忆，通过真实模型调用选择行动及生成对白；其他角色保持规则驱动作为对照。

### 必备知识

- **API 请求与响应**：把角色信息和允许动作交给模型，再从响应中取出决策。
- **角色提示与可见信息**：把角色设定、当前目标、可见事实和个人记忆交给模型，不预先用脚本选择好动作再让模型补写理由。
- **结构化输出**：把决策约定为行动类型、目标、需要时的对白及简短行动说明等字段；能解析 JSON 不代表字段或动作就合法。
- **配置与密钥**：模型名称、服务地址和凭据与业务代码分开；密钥不进入仓库或日志。
- **失败处理与用量**：设置超时和有限重试，区分认证错误与临时故障；了解 token、调用次数和费用。

### 动手产物

用一个 NPC 的角色、目标、当前状态、个人记忆和可用动作构造一次请求，解析模型的结构化决策，再交给执行逻辑校验。模型选择谈话时，由模型生成具体对白并实际传给对方。保留简短轨迹：输入的可见信息、模型提出的动作和对白、实际执行结果。请求模型给出简短行动说明即可，不要求输出内部推理过程。

真实模型模式不先经过当前 `choose_action()` 的精力或聊天间隔分支选动作；这些分支保留在规则模式中作对照。精力、交谈记录和目标作为模型判断的依据；程序保留地点、动作参数和执行前提的校验。

到此阶段再选择可用模型服务。没有可用服务时，可以用模拟响应练习协议，但须标明“模拟”；模拟响应不能证明真实模型能力。调用失败时采用明确的等待或规则回退，并在日志中说明实际使用的方式。

### 容易犯的错误

- 只修改提示词就相信模型一定遵守 JSON 格式或世界规则。
- 为每次移动传入全部世界历史，增加无关信息、延迟和成本。
- 把服务超时当作 NPC 已经完成行动，或静默回退后仍声称是模型决策。
- 先用条件分支决定动作，只让模型生成台词或理由，却称为模型自主决策。
- 不设超时、无限重试，或把真实密钥粘进代码。

### 进入下一阶段前的能力标准

- [ ] 完成至少一次真实调用，记录所用模型、可见输入、结构化决策及执行结果，不记录密钥。
- [ ] 指出请求构造、模型调用、响应解析和动作执行的位置，能解释四者的关系。
- [ ] 对格式错误、缺失字段和未知行动的响应进行可控演示，程序拒绝无效动作，世界状态不被破坏。
- [ ] 配置缺失、认证失败和超时均有明确提示；重试有上限，回退方式在日志中可见。
- [ ] 改变同一个 NPC 的输入状态，比较模型的实际选择，并区分“调用成功”和“行为符合预期”。
- [ ] 展示一次由真实模型选择对象并生成对白的交谈；接收方收到并记住实际内容。

若只完成模拟调用，记录为“协议练习完成，真实调用待验证”，不标记本阶段过关。

## 阶段 3：让行动形成循环

**目标：** 跑通“感知 → 决策 → 行动 → 世界更新 → 再感知”，让 NPC 提出短期目标与多步计划，并根据真实执行结果修订下一步。

### 必备知识

- **感知与反馈**：每轮提供当前可见状态，执行后返回成功、失败及实际变化；下一轮使用更新后的信息。
- **目标与计划**：模型依据角色和经历提出短期目标，把目标分成已有动作，并在遇到新信息或执行失败后调整；保留目标与计划的简短记录供后续决策使用。
- **工具与行动**：把移动、休息、交流等做成明确函数；模型提出参数，程序控制执行权。
- **合法性校验**：检查角色、地点、参数类型和前提条件，例如不存在的地点不能进入，不在场的角色不能进行当面交谈。
- **调度顺序**：定义每一时间步谁先行动，其他角色何时看到变化，避免状态互相覆盖。
- **停止与预算**：最大步数、请求超时、总耗时、调用与 token 上限；费用估算要注明价格依据和误差。

### 动手产物

给小镇增加可观察的 Agent 循环：每轮展示角色看到了什么、当前目标、提出什么动作、程序执行了什么、世界如何变化。先用少量步骤和简单动作验证，再增加动作种类。设计一个场景，让模型提出短期目标并形成多步计划；中途改变一项可见条件，检查它是否基于反馈合理更新计划。

费用预算可按已知价格估算，并在发起请求前检查；配合调用次数与输出长度上限控制开销。不能把事后统计费用当成提前限制，也不能声称估算是服务商账单的精确值。

### 容易犯的错误

- 直接执行模型生成的 Python 或 Shell，或允许模型任意改写世界状态。
- 只检查 JSON 语法，不检查动作的前提条件；失败后仍扣除物品或改变位置。
- 把“我已经到达”当作事实，没有把执行失败反馈给下一轮。
- 没有限制地持续循环；已经发出的请求超时后仍不断重试。

### 进入下一阶段前的能力标准

- [ ] 展示同一 NPC 连续多步的完整轨迹，至少一次后续决策实际利用了前一步的执行反馈。
- [ ] 保留模型提出的短期目标、多步计划及一次根据新信息或执行失败进行的修订；能说明哪些行为由模型决定、哪些变化由程序执行。
- [ ] 对未知动作、错误类型和不满足条件的动作分别验证拒绝行为；拒绝后不产生该动作的状态变化。
- [ ] 角色对白中出现“修改规则”等内容时，程序的行动权限和状态校验仍然有效。
- [ ] 用可控模拟分别触发步数、耗时和调用/token 预算限制，检查停止原因，且不再发起超出限制的新调用。
- [ ] 能解释费用估算方法和局限，并指出预算检查、模型决策、动作执行分别发生在哪里。

## 阶段 4：让角色拥有各自的经历

**目标：** 三个角色只依据自己能看到和记住的信息互动；小镇可以存读档，用固定场景检查行为。

### 必备知识

- **局部观察**：同一地点的人和事件通常可见，远处事件不自动进入角色输入；观察范围由程序定义。
- **独立记忆**：按角色保存亲历事件和实际收到的信息，保留时间及来源，避免共用一个全知记录。
- **交流与多人互动**：明确谁对谁说话、谁能听见、如何进入记忆；角色说的话可能不真实。
- **存读档**：保存足够的世界、时间和角色记忆；读取时检查格式、版本及必要字段。
- **检索与长度控制**：先用最近事件或关键词挑选相关记忆，限制输入长度，无需立即引入向量数据库。
- **日志与评测**：固定初始状态、测试输入和预期结果；区分确定性的程序检查与模型行为评估。

### 动手产物与固定评测

实现局部观察、各自记忆、同场交流和存读档，准备以下 **12 项待实施评测**。它们是验收设计，不代表已经实现或通过；预算项允许拆成多个子场景。

| 编号 | 场景 | 可观察的通过标准 |
| --- | --- | --- |
| 01 | 正常移动与状态更新 | 位置按允许动作改变，执行日志与世界状态一致 |
| 02 | 不存在的地点或错误参数 | 拒绝动作，位置及相关资源保持不变 |
| 03 | 同一地点发生事件 | 在观察范围内的 NPC 获得事件，记录时间和来源 |
| 04 | 远处事件 | 未在场且未收到转述的 NPC 输入和记忆中没有该事件 |
| 05 | 两个 NPC 的独立记忆 | 只告知甲的信息不会自动进入乙的记忆 |
| 06 | 同场对话 | 接收者实际收到内容并形成对应记忆，未在场者不自动获知 |
| 07 | 根据亲历事件继续行动 | 固定场景中，真实模型能使用相关经历选择符合目标的合法行动 |
| 08 | 询问未知事实 | 输入中确无依据时，真实模型承认不知道，不把猜测陈述为已知事实 |
| 09 | 保存、加载与继续运行 | 时间、位置、需求和记忆正确恢复；可继续执行一个合法步骤 |
| 10 | 存档损坏或字段缺失 | 清楚报告错误，不覆盖有效存档或静默生成伪造状态 |
| 11 | 服务异常或非法动作要求 | 超时/失败有可见处理；对白要求不能绕过行动规则 |
| 12 | 各项预算耗尽 | 分别触发步数、耗时、调用/token 上限，按约定停止并说明原因 |

程序行为可用确定性规则或模拟响应检查；第 07、08 项必须用真实模型评估，提前写下具体场景与成功条件，重复运行并记录实际成功比例。存档复现状态不等于保证模型下一次选择完全相同。

### 容易犯的错误

- 把所有事件发给每个 NPC，再仅靠提示词要求它“假装不知道”。
- 把传闻、模型生成的对白和亲眼所见混为事实，或让所有角色共用记忆。
- 无限累积历史，不处理上下文长度；只保存位置而忘记时间和记忆。
- 只展示一次有趣对话，不检查失败、隔离和预算边界。

### 进入下一阶段前的能力标准

- [ ] 全部 12 项均有实际记录，注明初始状态、执行方式、预期、结果与日期；模拟和真实模型分开标记。
- [ ] 程序约束、观察/记忆隔离、存档和预算检查均通过，模型行为达到事先写明的验收条件。
- [ ] 能从一个 NPC 的行动追溯到它实际获得的信息，说明另一个 NPC 为什么知道或不知道同一件事。
- [ ] 至少定位并修复一个实际发现的问题，重跑受影响场景及全部固定评测；未通过项保留记录。

## 阶段 5：独立完成可复现项目

**目标：** 他人能按文档运行小镇，你能独立解释系统、定位问题，并完成一个新需求。

### 必备知识

- **模块划分**：区分世界状态、规则、模型适配、记忆、调度与界面，避免一个改动牵连全部代码。
- **可复现运行**：记录 Python 版本、依赖、配置、启动和评测步骤，区分规则模式与真实模型模式。
- **需求拆分**：把“更像一个小镇”改成可验证行为，先写验收条件，再实现最小版本。
- **交付与诊断**：使用说明包含已实现功能、已知限制和常见错误；日志帮助区分服务故障与程序问题。

### 动手产物、易错点与验收

整理源码、示例世界、无密钥配置示例、依赖说明、存档约定和评测结果。独立选一个需求，例如“新增一个有开放时间的地点”或“增加一种需消耗物品的动作”，写清验收后完成。

常见错误是只在自己的环境能跑、文档把计划写成已实现、加入复杂框架却说不清数据流，以及改完新功能不复查旧行为。

- [ ] 在新的虚拟环境中按文档完成安装、配置和运行，不依赖未记录的全局包或个人路径。
- [ ] 演示三个 NPC 的模型决策、合法行动、局部观察和交流，并展示一次拒绝执行与一次预算停止。
- [ ] 完成一次存读档并继续运行，重跑 12 项评测，结果与当前版本对应。
- [ ] 独立实现一个新增需求，保留需求、修改、验证和自己的解释，能指出关键代码位置。
- [ ] 文档清楚区分实际支持的运行模式，源码、日志、配置及 Git 改动不含真实密钥。

## 如何学习与记录

沿用六种方法：**阶梯定位 → 聚焦一个任务 → 逐题检查 → 一页速查 → 少量资源 → 自己复述**。每次只做一个可观察的小改动；请 AI 检查实际证据，不替你预先打勾。

> 我正在用 AI 小镇学习 Agent，处于阶段【编号】。请一次只给我一个实践任务，不提前提供完整答案。等我提交修改、命令和输出后，再检查结果并问一道问题，让我解释数据怎样影响行为。证据不足时，不要判定我已经掌握。

在[主题学习记录](README.md#学习记录)填写实际产物、命令、输出和自己的解释。完成 AI 提供的骨架、读懂一段说明或做完首次练习，都不等于整个阶段已经过关。
